## Local preparation

The repository root is the plugin package root. It includes [package metadata](<https://github.com/sensen-jo/dsh-plugin-goal-map/blob/a1efb6ae8e847f8daba423b47ccc6f2bd9543af9/package.json>), the [host entry](<https://github.com/sensen-jo/dsh-plugin-goal-map/blob/a1efb6ae8e847f8daba423b47ccc6f2bd9543af9/index.mjs>), [bundle patch](<https://github.com/sensen-jo/dsh-plugin-goal-map/blob/a1efb6ae8e847f8daba423b47ccc6f2bd9543af9/cordis.patch.yml>), [built client](<https://github.com/sensen-jo/dsh-plugin-goal-map/blob/a1efb6ae8e847f8daba423b47ccc6f2bd9543af9/lib/client.js>), source, tests and documentation. It can be used as a local-directory bundle without moving files. A future Git source must resolve to this same root.

Run the dependency-free build, build check, Node tests, local validation and `npm run check:release`. A successful release check means static package metadata, license presence, source boundaries and built outputs passed. It does not check remote ownership, registry name availability, Git access, a live host installation or market indexing.

The release-gate tests cover complete public metadata and real relocated packages with missing license metadata, missing full license text, missing author, missing repository and `private:true`. Relocated builds copy all non-client entries from the explicit allowlist, including [LICENSE](<https://github.com/sensen-jo/dsh-plugin-goal-map/blob/a1efb6ae8e847f8daba423b47ccc6f2bd9543af9/LICENSE>).

## For later npm or source releases

1. Check the final package identity, registry name availability and repository control in the owner's trusted publication environment.
2. Review the final inventory and runtime hashes; retain the exact DSH `0.2.0-rc.2` engine and optional peer. Complete any separately required host/install review against that exact final candidate.
3. Keep the public repository root as the plugin bundle root. Download ZIP and local-directory installation are documented in the [README](<https://github.com/sensen-jo/dsh-plugin-goal-map/blob/a1efb6ae8e847f8daba423b47ccc6f2bd9543af9/README.md>); verify a Git clone installation before claiming that route tested.
4. For npm, inspect the exact tarball and publish that reviewed artifact with `--tag beta --access public --ignore-scripts`; after version and downloaded-byte verification, assign `latest` to this same beta only for the selected market's default-manifest discovery. This makes the beta the unversioned default, without changing its version or compatibility. Check both tags, integrity and downloaded bytes independently. The explicit allowlist excludes screenshots and Git helper files; README images and file links point to the pinned public source revision.
5. Follow the selected market's actual submission/manifest rules. Verify publication receipts and a listing URL separately; an installable package alone does not establish market acceptance.

The candidate has no uploader, credential access, remote push, postinstall downloader or automatic release workflow. No publication command is run by build, tests or validation. Only the tested DSH Web interfaces are declared compatible; newer market documentation does not establish newer-host compatibility.
